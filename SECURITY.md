# Security

## Reporting

Report a vulnerability through GitHub's private vulnerability reporting on this repository:
<https://github.com/J18Bharati/egressa/security/advisories/new>. Please do not open a public issue
for a security problem.

## Threat model

Egressa runs locally against source code you already have. The scanner itself makes no network
calls, has no telemetry, requires no credentials, and never reads `node_modules`. Two scripts in the
skills can reach the network, and only when you opt in:

- `plugin/skills/privacy-review/scripts/scan-transfers.sh` and `plugin/skills/egressa/scripts/scan.sh` fall back to
  `npx egressa@latest` only when `EGRESSA_ALLOW_NPX=1` is set.
- `plugin/skills/egressa/scripts/reconcile-aws.sh` makes read-only AWS calls, with your credentials, only
  when `EGRESSA_ALLOW_AWS=1` is set. No scan invokes it.

The realistic risks are therefore:

- **Malicious input files.** A crafted source file or lockfile could try to exploit a parser. All
  parsing goes through `oxc-parser`, `jsonc-parser` and `yaml`; parse failures are caught per file
  and reported as non-fatal errors rather than crashing the scan.
- **Reading outside the repository.** The scanned repository is treated as untrusted input, and so
  are its symlinks. The walk does not follow links, and every file is opened through a check that
  refuses a path whose real location is outside the scan root or that is not a regular file. The
  MCP server exposes no write tools.
- **The reviewed repository running code.** A review never executes anything from the repository
  under review. The skills run their scripts from the skill's own directory, never from the working
  directory, and resolve binaries from there too. The privacy review calls `git` inside the
  reviewed repository with hooks, `core.fsmonitor`, filter drivers, external diff, the pager and
  every network transport disabled, because a repository handed over with its `.git` directory
  brings its own git configuration. The gaps that remain are listed in
  [docs/LIMITATIONS.md](docs/LIMITATIONS.md).
- **Supply chain.** Nothing is published to npm yet, so there is no package to verify. The Claude
  Code plugin installs from a git ref: pin one you have read. Once releases exist, check whether the
  version you install carries an npm provenance attestation rather than assuming it does.
- **A committed build artifact.** `plugin/skills/privacy-review/bin/` holds a prebuilt copy of the CLI and
  the knowledge base, so the skill works without an install. It is generated by
  `pnpm skill:bundle` and never edited by hand, and `scripts/skill-bundle.test.ts` fails the build
  when its recorded tool or knowledge-base version drifts from source. Review it as a build
  artifact: regenerate rather than patch.

## The plugin hook

Installing the plugin registers a `PreToolUse` hook that runs on every `Write`, `Edit` and
`MultiEdit` in the session. That is a real surface, so what it does is bounded deliberately:

- It **reads only the text being added** (`content`, `new_string`, or each entry of `edits`) plus
  the target path. It does not read the file from disk, the rest of the repository, or the
  transcript.
- It **writes nothing** except a zero-byte marker under `CLAUDE_PLUGIN_DATA` to avoid repeating
  itself, and JSON on stdout.
- It makes **no network calls** and spawns no subprocesses.
- It **never blocks a tool call.** No permission decision is emitted and it never exits 2, the only
  exit code that blocks. Both are asserted by tests, including one in the claims contract.
- Anything unexpected **exits 0 in silence**, so a bug in the hook cannot break an editing session.

If you would rather not run it, install the skills without the plugin by copying `plugin/skills/` into
`.claude/skills/`, or disable the hook in your settings. The skills do not depend on it.

## Not a security scanner

Egressa reports data-transfer exposure, not vulnerabilities. It deliberately does not set
`security-severity` in SARIF output, because filing a privacy finding in a Security tab dressed as
a CVE would misrepresent what it found.
